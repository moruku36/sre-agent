# 模擬シグナル デモの詳細

[README](../README.ja.md) · [English](synthetic-signals.md)

## 模擬デモを実行する

SQLiteを利用できるPython 3.10以降が必要です。追加の依存パッケージや認証情報は不要です。リポジトリのルートから実行してください。

```sh
cd examples/synthetic_signals
demo_dir="$(mktemp -d)"
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" demo
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" demo
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" list
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" incidents
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" cost --policy cost_policy.json --as-of 2026-01-15T13:05:00Z
python3 -B -m unittest -v
```

初回は模擬シグナル25件を保存し、再送5件を除外します。2回目は30件すべてが再送として扱われ、新規保存はありません。各クラウドには料金・障害・復旧・遅延・欠損のサンプルがあります。遅延した観測値は保持し、欠損はゼロや正常ではなく「不明」とします。再送で元の記録は上書きされません。

読み取り専用の `incidents` コマンドは、`incidents` と `unapplied_health_evidence` を持つバージョン付きJSONオブジェクトを返します。デモではクラウドごとに1件、計5件の解決済みインシデントが出ます。インシデントのキーには開始時の障害イベントの送信元・スコープ・イベントIDを使い、根拠にはそれらのキーと各イベントの観測・受信時刻（UTC）を含めます。

障害をまとめるのは、クラウド・送信元・スコープ・環境・サービス・対象がすべて同じ場合だけです。イベントは受信順ではなく観測時刻順に並べ、より後の時刻に観測された遅延のない復旧イベントがあり、同時刻に障害がなければ解決と判定します。その後の再発は別のインシデントになります。観測の欠損、遅れて届いた復旧、判定が曖昧な復旧、対応する未解決の障害がない復旧は、理由付きで別に出力します。これは履歴から作るスナップショットなので、より早い障害イベントが後から追加されるとIDが変わることがあります。インシデント一覧が空でも、現時点で正常とは限りません。

DBが存在しない場合や保存済みの根拠が無効な場合は、空の結果を返さずエラーになります。元の料金シグナルは `list` で確認できます。どのコマンドもOpenClawやOpenAI Agents APIを呼び出さず、復旧操作も実行しません。

### 料金判定ポリシー

読み取り専用の `cost` コマンドには、ポリシーファイルと固定のUTC時刻 `--as-of` が必要です。バージョン1のポリシーは、クラウド・送信元・スコープ・環境・サービス・対象・料金種別・期待する通貨（`unit`）・金額の上限（`threshold`）・観測時刻からの経過秒数の上限（`max_age_seconds`）を指定し、ルールごとに判定と根拠を返します。条件を満たす観測値が上限を超えれば `anomaly`、上限以下ならそのルールに限り `within_limit` です。実績・予測・推定は別々に評価し、予測の異常を確定請求とはみなしません。デモは個々の観測値を比較するだけで、v1には請求期間の項目や集計・通貨換算はありません。

判定には指定時刻までに受信した根拠だけを使い、同じルールに該当する種別の最新受信を評価します。古い値への差し戻しはしません。受信済みのシグナルがない場合や、欠損・到着遅延・鮮度超過・矛盾・観測と到着の順序逆転・不一致がある場合は、理由付きの `unknown` とし、料金ゼロや上限内とはみなしません。観測から受信までが1時間を超えると到着遅延、判定時刻でルールの許容経過時間を超えると鮮度超過です。別の料金種別で代用することもありません。判定対象外の行や指定時刻より後に受信した行も含め、DB内の全行を検証します。DBの不在、不正なポリシーや保存データは、空の結果ではなくエラーになります。

上限との比較や同じ観測時刻の金額の矛盾判定には、ポリシーのJSONとSQLiteに実際に保存されたJSONの数値を、十進数としてそのまま使います。結果の金額は二進浮動小数点数に丸めずJSON数値で出力します。精度を保つには、読み手側も十進数として読み取ってください。保存前に失われた精度は復元できません。既存DBの移行は不要です。

SQLiteは `mode=ro` で開くため、データやスキーマへの書き込みは行いません。ただしWALモードでは、SQLiteが補助ファイル（`-wal` と `-shm`）を必要としたり、作成したりする場合があります。

同梱の模擬ポリシーでは、AWSは観測欠損で不明、AzureはJPYの予測が異常、GCPは推定の到着遅延で不明、OCIはルールが要求する予測を受信していないため不明、さくらのクラウドはJPYの予測が上限内になります。デモの再送後も、同じ判定時刻で実行すれば同一のJSONが返ります。

### OpenClaw向けのローカル模擬ハンドオフ

デモの実行後、指定時点までに受信した障害と料金のスナップショットを一度に読み取れます。

```sh
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" handoff \
  --policy cost_policy.json --as-of 2026-01-15T12:21:00Z
```

標準出力を1つのJSONオブジェクトとして読み、`kind: "synthetic_sre_handoff"` と `version: 1` を確認します。判定時刻の `as_of`、障害相関の `incidents` と `unapplied_health_evidence`、および `cost` の `classifications` と同じ形式の `cost_classifications` が含まれます。数値の精度を保つには、例えばPythonの `json.load(stream, parse_float=Decimal)` で読み取ります。

障害と料金には、SQLiteの同じ読み取り専用スナップショットを使います。全行を検証したうえで、`received_at <= as_of` の根拠だけを判定に使います。デモの5件は `12:21:00Z` では未解決で、復旧を受信する `12:22:00Z` には解決済みです。模擬データの根拠ID・参照と、不明とした理由を保持します。障害一覧が空でも、現時点で正常とは限りません。入力の不備や欠落があればJSONは出力せず、エラー終了します。

これは模擬データをローカルで取得するための形式であり、認証付きのOpenClaw連携ではありません。データ送信・受領確認は行わず、シグナルやスキーマも変更しません。同じDB、ポリシー、判定時刻からは同じJSONが返ります。WAL補助ファイルの扱いは前節のとおりです。

### 模擬インシデントを1件取得する

ハンドオフの `incidents` 配列から `incident_id` をコピーし、同じ判定時刻を指定すると、その時点の結果を取得できます。デモのAWSのインシデントは `12:21:00Z` では未解決で、復旧を受信する `12:22:00Z` に解決済みになります。

```sh
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" get-incident \
  --as-of 2026-01-15T12:21:00Z \
  --incident-id 'health:synthetic-aws-01/synthetic-aws-prod/synthetic-aws-outage-0001'
```

出力は1つのJSONオブジェクトです。`kind: "synthetic_sre_incident_detail"`、`version: 1`、判定時刻 `as_of`、指定した `incident_id`、および `found` または `not_found` を示す `status` を含みます。完全一致するIDがあれば、`incident` にハンドオフと同じ項目が入り、障害自体の状態（`open` または `resolved`）と根拠も含まれます。形式が正しくても完全一致するIDがなければ、`not_found` と `incident: null` を返し、終了コードは0です。これは指定時点のスナップショットにそのIDがないことを示すだけで、サービスが正常だという意味ではありません。

料金ポリシーは不要です。読み取り専用のスナップショットを、指定時刻より後に受信した行も含めて検証し、`as_of` 以前（指定時刻と同時を含む）に受信した根拠だけを相関に使います。他のインシデント、判定に使われなかった根拠、料金判定の結果は返しません。時刻・ID・DBの内容が不正な場合や、必須オプション・DBがない場合は、JSONを出力せずにエラー終了します。これはローカルの模擬データを読み取る機能であり、実際のOpenClaw連携ではありません。

### ローカル模擬調査レポート

上のデモDBからハンドオフを取得し、バイト列を変更せずに保存します。呼び出し側が指定したインシデント1件について、同梱の模擬応答を照合します。

```sh
python3 -B sre_mvp.py --db "$demo_dir/signals.sqlite3" handoff \
  --policy cost_policy.json --as-of 2026-01-15T12:21:00Z > "$demo_dir/handoff.json"
python3 -B sre_investigation.py --handoff "$demo_dir/handoff.json" \
  --response investigation_mock.json \
  --incident-id 'health:synthetic-aws-01/synthetic-aws-prod/synthetic-aws-outage-0001'
```

同梱の[模擬応答](../examples/synthetic_signals/investigation_mock.json)は手書きで、APIによる生成ではありません。別のスナップショットを試す場合は、末尾の改行も含めたファイルの正確なバイト列のSHA-256を `handoff_sha256` に記録し、そのファイル内の完全なインシデントIDを指定してください。JSONを整形し直すだけでもハッシュは変わります。`--incident-id` と模擬応答のIDは一致する必要があります。引用では `source`、`scope`、`event_id`、不透明な参照文字列 `evidence` の4項目すべてを指定します。その案件に紐づき、`as_of` までに受信した根拠だけを引用できます。料金、相関に使われなかった根拠、別案件の根拠は対象外です。

レポートの `observed_evidence` には、引用元の記録をハンドオフと同じ順序で、受信時刻・鮮度とともに載せます。原因候補（支持・反証の引用を含む）、不明点、次の確認事項は別枠で、事実や命令としては扱いません。`references_validated` は紐づけを確かめたことを示すだけで、作成者の認証、因果関係の証明、現時点の正常性の確認ではありません。応答が未完了の場合、IDの欠落・重複、引用の不一致、未定義の応答フィールドがある場合は、レポートを出力せずエラーになります。このコマンドは2つのローカルJSONだけを読み、参照先へのアクセス、モデル呼び出し、承認、復旧操作は行いません。
